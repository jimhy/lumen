## 与桌面端 `remote_ws.rs` 刻意不同的三处（§7.4，**照抄桌面实现是错的**）

1. **退避**：桌面固定 3s；移动端指数 + 抖动（1s → 30s 上限）。一次服务端重启会让同一批用户
   在同一时刻掉线，固定间隔意味着他们之后每 3 秒**同频**敲一次——而服务端出站通道是无界
   mpsc、**零背压**。「网络恢复 / 回前台」时调 `kick()` 立即重连、不等退避。
2. **心跳**：仍 25s 发应用层 `Ping`（对齐服务端 25s `last_seen` 节流与 45s 在线窗口），
   但**额外**加 Pong 看门狗：15s 收不到就主动断开重连。服务端**不发 Ping、也没有读超时**，
   移动网络的半开连接极常见——没有这条，界面一切正常、心跳照发，但什么都不动。
3. **生命周期**：进后台先起 25s 宽限计时器（应付「切出去看一眼验证码」），到点主动关 socket。

## 三条硬约束

- **token 走 `Authorization` 头**，服务端 `ws.rs` 明确不接受 query（避免反代日志泄漏）。
  ⚠ 这条同时是「将来出 Web 版」的硬阻塞点（浏览器 `WebSocket()` 设不了请求头）。
- **`send()` 在无连接时丢弃**（与桌面端同语义，这里让它返回 `bool` 而不是纯静默）
  ⇒ 需要送达保证的请求必须走 outbox + `req_id` 超时（片 10）。
- **服务端零背压**（R11/R24）：客户端要自我节制——登录失败退避、列表刷新去重（`DeviceListController`
  已合并并发刷新）、outbox 重发最小间隔、backfill 分块 ≤ 256 KiB。

## 为什么定时器与 socket 都是注入的

片 5 有四条靠时间驱动的行为，每一条错了都只在真机弱网下现形：

| 计时器 | 时长 | 错了会怎样 |
|---|---|---|
| 心跳 | 25s | 服务端 45s 在线窗口过期，设备在别人的列表里显示离线 |
| Pong 看门狗 | 15s | 半开连接不被发现 |
| 后台宽限 | 25s | 切出去看一眼就断线，或反过来长期占着 socket |
| 发起超时 | 12s | 老服务端完全无回音，UI 无限转圈（在 `state/link_controller.dart`） |

直接用 `Timer` 意味着测它们要**真的等** 12–25 秒，还测不了「刚好没到 / 刚好到了」的边界——
现实里的结果一定是这四条没有测试。注入之后，25 秒是一行 `clock.advance(...)`。

同理 `ws_client.dart` 刻意零 `dart:io` 依赖（真实现单独放 `io_ws_socket.dart`），
于是「连上 → 心跳 → 半开 → 重连 → 后台 → 回前台」整条线能在纯 Dart 里跑完。

**不用 `package:fake_async`**：它是 `flutter_test` 的传递依赖，直接 import 会被
`depend_on_referenced_packages` 拦下；显式加进 dev_dependencies 又要动 `pubspec.lock`
（本机 pub 的坑见 `tool/test.sh` 头部）。这里要假的只有「延迟执行」一件事。

## 401 → refresh → retry 为什么是显式写的，不是 dio 拦截器

拦截器版本短，但这个协议下有两个会真踩的坑：

1. **递归续期**：续期请求自己 401 时拦截器会再触发一次续期——而服务端 JWT 过期后 `refresh`
   必然 401，于是变成一个打服务端的循环。这里让续期走**不带重试**的通道，结构上不可能递归。
2. **重试次数说不清**：「只重试一次」在拦截器里要靠给 `RequestOptions` 打标记，而那个标记
   在重放时容易丢。显式写就是一行 `if`。

**续期失败 ⇒ 清本地凭据 + 退回登录页**，不是重试：服务端 `refresh` 除验签外还会确认设备行
仍存在，所以「续期也 401」意味着 token 真过期了或这台设备被删了。留着失效凭据会让后续每个
请求都走一遍「401 → 续期 → 失败」，把一次失效放大成持续打服务端。
