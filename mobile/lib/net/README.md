## 与桌面端 `remote_ws.rs` 刻意不同的三处（§7.4，**照抄桌面实现是错的**）

1. **退避**：桌面固定 3s；移动端指数 + 抖动（1s → 30s 上限），避免地铁隧道里全国用户同频重连。
   并在「连通性变化 / App 回前台」时调 `kick()` 立即重置退避重连。
2. **心跳**：仍 25s 发 `Ping`（对齐服务端 25s 节流与 45s 在线窗口），但**额外加 Pong 看门狗**：
   15s 收不到 `Pong` 就主动断开重连。移动网络的半开连接极常见，而**服务端不发 Ping、也没有读超时**——
   没有这个看门狗，半开连接会一直装作活着。
3. **生命周期**：进后台先起 25s 宽限计时器（应付快速切 App 查资料），到点主动关 socket。

## 三条硬约束

- **token 必须走 `Authorization` 头**，不能放 query：服务端 `ws.rs` 明确不接受 query，
  理由是避免反代日志泄漏。`IOWebSocketChannel.connect(headers:)` 支持自定义头；
  ⚠ **若将来要出 Web 版，这条会成为硬阻塞点**（浏览器 WebSocket API 不能设请求头）。
- **`send()` 在无连接时静默丢弃**（与桌面端同语义）⇒ **所有需要送达保证的请求都必须走
  outbox + `req_id` 超时**，不能假设 `send` 成功。
- **服务端零背压**（R11/R24）：客户端侧要自我节制——登录失败退避、outbox 重发去重与最小间隔、
  backfill 分块 ≤ 256 KiB。
